# FRACTAL RUN NAVI

住所と「今日走りたい距離」を入れると、**クチコミの多い人気スポットを経由するランニングコース**を
自動で組み立てるWebアプリ。iPhoneのSafariでそのまま動く（インストール不要・PWA対応）。

👉 **https://takase-creator.github.io/fractal-run-navi/**

---

## できること

| | |
|---|---|
| コース生成 | 出発地＋距離（1/3/5/10/15km・0.5km刻みで30kmまで）→ 実際の徒歩ルートを3案 |
| コースの形 | **周回**（出発地に戻る・行きと帰りで景色が変わる）／**往復**／**片道** |
| 立ち寄り先 | Googleの**クチコミ件数**が多い順に優先。おまかせ／景色・公園／名所・神社仏閣／カフェ・飲食 |
| 坂の好み | 各コースの**獲得標高**を実測。おまかせ／なるべく平坦に／坂を入れる で並べ替え |
| **走行中の地図** | コース・現在地・走った軌跡・**残り距離**をライブ表示。コースを外れると警告 |
| ナビ | ワンタップで **Googleマップアプリ**の徒歩ナビへ（経由地込み） |
| 天気 | 気温・体感・湿度・降水確率と、**暑さに応じたラン向けの注意** |
| コース保存 | 気に入ったコースを⭐で保存。オフラインでも開けて何度でも走れる |
| **SNS投稿** | 3形式のテキストを生成→編集→コピー。ルート図の画像も作れる |
| 所要時間 | 自分の実績ペースから予測。走るほど精度が上がる |
| ラン記録 | GPSで距離・タイム・1kmスプリットを記録（スリープ抑止つき） |
| ヘルスケア連携 | `export.xml` を読み込んで過去のランからペースを算出／記録をCSV・GPXで書き出し |

## 2つのデータソース

| | Google モード | オープンデータ モード（既定） |
|---|---|---|
| 人気度の指標 | **Googleのクチコミ件数**＋星評価 | **Wikipedia月間閲覧数** ＋ OSMのタグ |
| スポット検索 | Places API (New) `searchNearby` | Overpass API |
| 徒歩ルート | Directions API | FOSSGIS OSRM（`routed-foot`） |
| 住所検索 | Geocoding API | Nominatim |
| 準備 | APIキーが必要（無料枠あり） | **不要・すぐ使える** |

設定画面でAPIキーを入れるとGoogleモードに切り替わる。キーは**この端末のlocalStorageにだけ**保存され、
サーバーには一切送信されない。

### Googleモードを使う場合

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクト作成
2. **Maps JavaScript API** / **Places API (New)** / **Directions API** / **Geocoding API** を有効化
3. 認証情報 → APIキーを作成
4. キーの制限 → アプリケーションの制限＝**ウェブサイト** → `https://takase-creator.github.io/*` を追加
5. アプリの設定画面に貼り付け

1回の検索で消費するAPIコールは **スポット検索5〜8回＋ルート計算4〜7回**。
スポット検索結果は同じ場所・同じ距離なら7日間キャッシュするので、いつもの出発地なら2回目以降はほぼ0。

## コース生成のしくみ

**周回モード**は、出発地を頂点のひとつに含む正多角形として近似する。
頂点数 V の正多角形の外接円半径 Rc と周長 T の関係は

```
T = V · 2Rc · sin(π/V)   →   Rc = T / (detour · V · 2 · sin(π/V))
```

`detour` は直線距離に対する実際の道路距離の比（初期値 1.28）。多角形の中心を出発地から
方位 θ₀ に Rc だけ離した位置に置き、θ₀ を振ることで構造の違う周回コースを複数作る。
各頂点は、その近傍で最も人気のあるスポットにスナップする（人気度 − 理想位置からのズレ×係数）。

頂点iは出発地から `2·Rc·sin(iπ/V)` の位置に来るので、スポットを探す帯もその範囲に合わせる。
ここを外すと遠い頂点が探索圏外に落ちて、コースが目標距離に収束しない。

計算量を抑えるため、

1. 直線距離での見積もり（API不要）で候補を絞る
2. 生き残った候補だけ実際にルーティング
3. 最初の実ルートから `detour` を学習し直し、1回の補正で目標距離に収束させる

**片道**は目標距離Tの位置、**往復**はT/2の位置にゴールを置いて同じ手順を踏む。

### 広い場所は「点」ではなく「範囲」として扱う

代々木公園は79ha あり、重心は原宿駅から555mだが園内は1km以上先まで続く。
重心1点で判定すると5km周回の探索帯（781〜1739m）から外れて候補に出てこない。
そこで面積のある地物はバウンディングボックスを保持し、

- **帯の判定**：出発地からboxまでの最近距離〜最遠距離が帯と交差すれば候補にする
- **経由点**：boxを理想位置でクランプした点＝実際に足を踏み入れる縁を経由点にする

この修正で、原宿駅・5km・周回が「明治神宮 → 新宿御苑」「代々木公園 → 明治神宮」を返すようになった。

### 共有サーバーとの付き合い方

Overpass も OSRM も寄付で動く共有インフラなので、リクエストは1.1秒間隔に直列化し、
429/504 を受けたら指数バックオフで再試行しつつ90秒間は間隔を最大6秒まで広げる。
Overpassは主インスタンスが落ちていたらミラーに切り替える。
半径3.5km超の探索では `[wikidata]` 付きの地物と面積のある緑地に限定して負荷を落とす
（そもそもスコア上位に来るのはこの2種類なので、実用上の取りこぼしはない）。

## Apple ヘルスケアについて（正直な話）

iOSはWebブラウザにHealthKitを開放していないため、Safariから直接ヘルスケアを読み書きすることは**できない**。
このアプリは公式のデータ書き出しを橋渡しに使う。

**ヘルスケア → 自分のペースを取り込む**
ヘルスケアアプリ → 右上のプロフィール → 「すべてのヘルスケアデータを書き出す」 →
できたzipを解凍 → 中の `export.xml` を設定画面から読み込む。
数百MBあるのでDOMには載せず、6MBずつスライスして走査する。
`<Workout>` は iOS 14以前（`totalDistance` 属性）と iOS 15以降（`<WorkoutStatistics>` 子要素）の
両方の書式に対応。

**アプリの記録 → ヘルスケアへ戻す**
CSV／GPXで書き出せる。ヘルスケアへの直接書き込みはOS制約でできないので、
RunGap・HealthFit などの取り込み対応アプリを経由する。

## ローカルで動かす

ES modulesは使っていないが、`file://` だとCORSでAPIが叩けないのでHTTP経由で開く。

```bash
cd ~/run-navi && python3 -m http.server 8080
```

## 坂の測り方

Open-Meteo の標高APIでルート上を34点リサンプルし、獲得標高・最大勾配・プロフィールを出す。
候補4本ぶんのサンプルは1リクエストにまとめる（100点/回まで）。
DEMのノイズを拾って坂を水増ししないよう、隣接点の差が **1.5m未満なら無視**する。

`坂の好み` は再検索せずその場で並べ替える。獲得標高25m/kmを「しっかり坂のある街ルート」の
基準にして、`baseScore ± 係数 × 坂の強さ` で並べ直す（おまかせに戻せば元の順序に戻る）。

## 走行中の画面

計画コース（明るい緑）、走った軌跡（ピンク）、現在地、残り距離をライブ表示する。
残り距離は現在地をコースのポリラインに射影して求める。

地図の再センタリングは**1秒に1回・アニメーションなし**。マーカーはDOM要素、軌跡はCanvasで
描かれるため、完了前に上書きされるパン動作を挟むと両者が目に見えてずれる。
ズームは最初の1回だけ16に合わせ、以降はユーザーの操作を尊重する。

コース逸脱の警告は **90m以上が3回続いたら**。単発のGPSの暴れで走行中に何度も警告が出ると
かえって邪魔になる。周回コースでは復路が近くを通るので、この判定は
「見逃しはあっても誤警告はしない」側に倒してある。

## SNSへの貼り付け

走り終えると記録の詳細画面が開き、そこから3形式のテキストを作れる（コース詳細からは
「これから走るコース」としても作れる）。生成した文面はその場で編集してからコピーする。

- **標準** — 距離／タイム／ペース／獲得標高／コース、Threads・Facebook向け
- **X向け（短め）** — 1投稿に収まる長さ。CJKを2カウントする X の数え方で残り文字数を表示
- **詳細** — スプリット全ラップとベストラップ入り

日本語の桁揃えは**全角スペース（U+3000）**で行う。SNSはプロポーショナルフォントで描画するため、
半角スペースで揃えた表は投稿すると必ず崩れる。全角スペースは隣の漢字と同じ幅なので揃う。

**ルート図の画像**は地図タイルを使わず、軌跡のポリラインだけをCanvasに描く。
タイルのCORSでcanvasがtaintされる心配がなく、圏外でも生成できる。
1080×1080（Instagram・X兼用）。`navigator.share({files})` が使える端末では直接共有、
使えなければPNGとして保存。

クリップボードは `navigator.clipboard.writeText` を**タップハンドラから同期的に**呼ぶ
（iOS Safariは間に await を挟むと拒否する）。失敗時はテキストエリアを選択状態にして、
長押し→コピーに逃がす。

## 構成

```
index.html            画面（5ビュー：コース／詳細／走る／履歴／設定）
css/app.css
js/util.js            測地計算（haversine・方位・目標点）と整形・レート制限
js/store.js           localStorage永続化・ペースモデル・POIキャッシュ・保存コース
js/providers.js       Google / OSM の2バックエンド（同一インターフェース）
js/terrain.js         標高取得・獲得標高・プロフィールSVG
js/weather.js         天気と暑さ指数のアドバイス
js/planner.js         コース生成アルゴリズム
js/mapview.js         Leaflet描画（詳細地図＋走行中ライブ地図）
js/tracker.js         GPS記録・Wake Lock・スプリット・GPX
js/health.js          export.xml ストリーミング解析・CSV取込
js/app.js             UI配線
sw.js                 Service Worker
```

## データの扱い

出発地履歴・走行記録・APIキー・ヘルスケアの取込結果は、すべて**端末のlocalStorageのみ**に保存される。
アプリ独自のサーバーは存在せず、外部に送信されるのは地図タイル・経路計算・スポット検索の
リクエストだけ。
